1) Потому что по заданию нужно, чтобы операции были симметричны, то есть можно было сделать (f + k) или аналогично (k + f). Если бы это был метод класса, он требовал бы указатель на объект как первый аргумент, то есть работал бы только случай (f + k), а (k + f) не компилировался. потому что не мог найти объект типа Fraction. Поэтому подходит friend-функция, а не метод класса. Friend нужен чтобы функция имела доступ к приватным полям класса. Иначе пришлось бы прописывать геттеры для каждого поля, чтобы сложить их.
2) Мутабельные операторы получают по ссылке сам объект, изменяют его, и возвращают ссылку на него же. Ссылка возвращается по аналогии с операндами встроенных типов (как в int x; x+=2;) То есть меняется сам объект, новый не создаётся. Тем более это методы, а не функции, то есть они работают с конкретным экземпляром класса. Иммутабельный оператор является функцией, не изменяет переданные объекты (они передаются как const) и создаёт внутри новый экземпляр класса - локальный объект, который живёт только внутри функции. Наружу он возвращает объект класса по значению.
3) Выводит: 4294967295/2. Для оператора * у Function есть 3 перегрузки:
friend Fraction operator*(const Fraction &a, const Fraction &b);
friend Fraction operator*(const Fraction &a, std::uint32_t k);
friend Fraction operator*(std::uint32_t k, const Fraction &b);
Программа выбирает вторую, то есть из приведения (-1) в Franction и в uint32_t программа преобразует (-1) в uint32_t, происходит переполнение, в 2^32 - 1, и при умножении на дробь 1/2 число делится на 2. Программа выбирает вторую перегрузку, потому что для этого требуется стандартное преобразование, а если (-1) приводить к fraction, то нужно брать пользовательское преобразование.
4) В потомках Expression определена функция print, которая определяет формат вывода. В самом expression эта функция виртуальная и не имеет определения (=0), то есть гарантируется, что в невиртуальных потомках она будет определена. Оператор вывода определён только для expression, поэтому при попытке вывода любого его потомка программа обращается к этому оператору родителя, в теле которого прописано, что надо вывести выражение через функцию print. Поскольку << принимает Expression& e, то есть ссылку, это может быть любой потомок этого класса. Тогда e.print(os); будет вызывать функцию, соответствующую именно этому типу узлов, то есть этому потомку.
5) Если бы деструктор был не виртуальный, то в целом строку virtual ~Expression() = default; можно было бы не прописывать, был бы просто default деструктор. Но тогда бы программа работала некорректно. Поскольку деструктор виртуальный, программа определяет, что по указателю на Expression лежит не объект класса Expression, а объект какого-то его класса-потомка, и вызывает декструктор этого типа. Иначе вызывался бы деуструктор родительского класса, который не подойдёт, потому что, например, в Add и в Expression даже разное количество полей.
